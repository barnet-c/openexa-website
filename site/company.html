01MissionAgents for the world’s high-value lifecycles

Software has always waited for a person to decide. It doesn’t have to anymore. The work that runs the world — the approvals, the exceptions, the handoffs, the records — is becoming an agent’s work. Not one agent. Thousands, each with a single job, its own permissions and its own line in the ledger. OpenEXA builds those agents and the infrastructure they run on. The first lifecycle is already live.

Why lifecycles

The most valuable processes in the economy — settlement, creation and redemption, letters of credit, securitization, batch release — share six traits that make them expensive for people and exactly right for narrow, verifiable agents on a shared ledger.

04How we buildFour things that never change

The lifecycles vary. Four constants don’t.

Across every phase of the platform — one agent, master and copy, open rails — these four principles hold. They are the research contribution. The product is what happens when you hold them constant and let the lifecycles vary.

C-01Boundary

Agents decide. Code executes.

The top four layers estimate and reason. The bottom four are deterministic: idempotent execution, authenticated tools, scoped permissions. The line between them is a typed schema.

C-02Scope

No single agent sees the whole job.

Each agent is scoped to one gate and does one thing. Its output is a proposal — a data structure until something downstream permits it. When it is wrong, we know which agent, at which gate.

C-03Permission

Nothing an agent believes can move what it is not permitted to.

Capabilities are held per agent and per tool and enforced by the runtime. Custody never moves. No agent and no tool has withdrawal rights.

C-04Record

Anything that settles is written to a ledger nobody can edit.

Append-only, hash-chained, replayable — and written only after an independent counterparty confirms. Every live session becomes a dataset.
